# Phase 2 정리 노트

Phase 2(백엔드, Google 로그인, YouTube 연결)에서 만든 것과 기획서(`SPEC.md`)와 달라진 점, 완료 기준 점검, 남은 과제입니다. (2026-10-05, P2-1 ~ P2-6 완료, P2-7 일부)
결정의 자세한 내용은 `DECISIONS.md`의 번호를 보세요.

## 1. 지금 되는 것

- Google 로그인(2단계: 기본 정보 → YouTube 권한은 처음 한 번), 등록된 이메일만 사용, 7일 로그인 유지, 로그인이 끝나면 로그인 화면으로
- 좋아요 전체(YouTube가 주는 최대 약 5,000개)와 재생목록 조회, 서버 메모리에 보관
- 좋아요 취소, 재생목록으로 이동(+좋아요 취소), 재생목록에서 제거를 서버의 백그라운드 작업으로 처리. 롤백, 429 재시도, 할당량 초과 중단, Retry Failed 포함
- 할당량 기록(실패·재시도 포함)과 화면 표시, 작업 전 서버에서도 할당량 확인
- 30일 지난 작업 기록과 할당량 기록을 매일 자동 삭제
- 개인정보처리방침(연락처는 `backend/.env`의 `ADMIN_EMAIL`)
- 개발 중에는 설정 하나로 가짜 데이터 / 실제 서버 전환, 운영 빌드에는 가짜 데이터와 DEV 패널이 들어가지 않음
- 자동 테스트: 백엔드 80개(`cd backend && uv run pytest`)

## 3. Acceptance Criteria 다시 점검 (SPEC.md 13장, 실제 API 기준)

| 기준 | 판정 | 이유 |
|---|---|---|
| 승인 안 된 사용자는 Pending Approval 화면, admin은 메일 알림 | 충족 (56으로 대체) | 허용 목록 방식으로 바뀜. 미등록·disabled는 Access Denied에서 자기 이메일을 봄. 메일 알림은 없앰 |
| 승인된 사용자만 좋아요 목록과 재생목록 조회 | 충족 | YouTube 관련 API는 모두 매 요청 `active`를 DB에서 확인 |
| 좋아요 한 영상 전체를 작은 썸네일 리스트로 | **부분 충족** | YouTube가 약 5,000개까지만 줌(59). 넘는 계정에는 안내 문구로 알리고, 좋아요를 정리한 뒤 Resync하면 더 오래된 것이 보임(61) |
| 제목 검색, 채널, 카테고리, 길이·업로드 날짜 정렬 | 충족 | 불러온 목록 위에서 처리(0 units) |
| Resync로 최신 상태 | 충족 | 예상 units 표시, 작업 직후 10초 대기(55, 62) |
| 최대 100개 좋아요 취소 / 재생목록으로 이동 | 충족 | 화면과 서버 모두 100개 검사 |
| 이미 있는 영상은 중복 추가 안 됨 | 충족 | 작업 시작 때 대상 재생목록을 YouTube에서 새로 읽어 확인 |
| "이동 + 좋아요 취소"에서 한 단계만 성공한 상태 없음 (롤백 실패 예외) | **부분 충족** | 롤백하고, 작업이 멈출 때도 롤백한 뒤 멈춤. 단, 추가와 좋아요 취소 사이에 **서버가 꺼지면** 반쯤 된 상태가 남을 수 있음. 그 항목은 Not processed로 보이고, `Retry Failed`가 "이미 있음 → 좋아요 취소만"으로 정리함(63) |
| 재생목록에서 중복, 삭제/비공개, 선택한 영상 제거 | 충족 | |
| 오늘 남은 할당량과 실행 전 예상 소모량 | 충족 | |
| 할당량이 부족하면 실행 불가 + 몇 개까지 가능한지 안내 | 충족 | 화면과 서버(DB 기록 기준) 모두 검사 |
| 작업 진행률, 성공/실패 개수, 실패만 다시 실행 | 충족 | 서버 재시작으로 중단된 작업도 Retry Failed 가능 |
| 탭을 닫았다 다시 열어도 작업 결과 확인 | 충족 | 작업은 서버에서 계속되고 최근 작업 하나를 보여줌(12). 서버가 꺼지면 중단 처리(63) |
